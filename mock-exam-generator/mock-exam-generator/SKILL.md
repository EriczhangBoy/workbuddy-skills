# 模拟题库生成器（mock-exam-generator）

为指定岗位生成「综合能力测试 50% + 专业能力测试 50%」的交互式模拟题库练习版 HTML（单文件、手机友好、进度自动保存）。

## 何时使用

- 用户想要针对某岗位/职业的模拟题、练习题、笔试题库
- 用户提供或可询问出：岗位名称、岗位职责/要求、专业方向、综合测试偏好、难度、套数与题量
- 产出要求是带交互的 HTML 练习页面（判题 + 答案 + 复习），而非 Word/PDF

## 使用流程（严格执行）

### 第 0 步：收集参数（先确认可选项，再出题）

**判定规则（消除歧义，不要猜也不要盲目走默认）：**

- **必填项**（岗位名称、专业知识类型）：用户未提供 → **必须先用 `AskUserQuestion` 询问**，不得用占位词猜测
- **可选项**（整体难度 / 套数 / 每套题量 / 是否含答案解析 / 综合测试涉及方向 / 是否加问答题 / 是否增加资料分析题）：用户未显式给出 → **用 `AskUserQuestion` 一次性合并确认全部可选项**（一个工具调用、一个 question 数组，节省往返）
- **例外**：用户明确说"直接生成 / 按默认 / 你定 / 结合确定" 等 → 跳过询问，所有未提项按下表默认执行，并在最终回复里列出所取默认值

**向用户收集以下参数（按上述规则处理）：**

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| 岗位名称 | 如「给排水技术岗」「水厂设备管理岗」 | 必填 |
| 岗位职责/要求 | 出专业题与策略选题的素材来源（越具体越好） | 尽量收集 |
| 专业知识类型 | 专业能力测试的取材领域（如给排水、金融、法律、HR…） | 必填 |
| 综合测试涉及方向 | 微调常识判断取材比重（如"多经济金融常识"）；不填则通用（时政/历史/地理/文化/科技/法律/经济/生活） | 通用 |
| 整体难度 | 简单 / 中等 / 困难 | 中等 |
| 套数 | 默认 3（可 1~5） | 3 |
| 每套题量 | 默认综合 25 + 专业 25 = 50（若启用资料分析则综合追加每组 4~5 题） | 50 |
| 是否含答案解析 | 默认含（每题解析写进答案表与"查看答案"） | 含 |
| 每套问答题数 | 专业情景问答题（主观题，附参考要点）。**生成前询问用户是否需要问答题，默认加上**（仅当用户明确"不要问答题"才设为 0） | 3 |
| 每套资料分析组数 | 表格数据分析题（放综合区末尾，类似行测"资料分析"）。**默认不加（0 组），必须用 `AskUserQuestion` 询问用户是否增加**（"不加"或"每套 2 组"，仅用户确定"要"才启用）；确定后默认每套 2 组材料，每组材料配 4~5 道单选或多选 | 0 |

### 第 1 步：编制题库

1. 读取 `references/出题规范.md`，按其结构、取材范围与难度分级出题。
2. 在工作目录创建 `bank/`，按 `references/页面与交互规范.md` §3 的数据格式，每套写一个 `set1.md`、`set2.md`…
   - 综合区严禁出现岗位专业词（专业词表由第 2 步的 `--banned` 传入）。
   - 每题必填答案与解析；单选题答案唯一；计算题必须实际演算。
   - **正确答案落点控制（源头避免规律）**：出题时"先定正确项落点、再写选项"——每道题先决定正确项放哪个字母位置（刻意打散，不用 ABCD 轮转、不固定 A），最好先写干扰项再插入正确项；整卷落点各字母约占 1/4、无周期、避免连续 3 个相同答案；编完按题号列出答案字母序列人工自检。**不要靠事后脚本随机/轮转**（轮转会形成 A,B,C,D 周期规律，同样可预测）。（方法见 `references/出题规范.md` §5.5）
   - **问答题**：默认每套 3 道，放在专业部分之后，编号接续（如客观题 1-50，问答题 51-53），每道为岗位专业情景题，必须附 `> 参考要点：`（3~5 点），格式见 `references/页面与交互规范.md` §3。
   - **资料分析（仅用户确定要时才编制）**：放在综合区末尾独立模块（如"六、资料分析（2 组材料，每组 4~5 题）"），默认每套 **2 组**材料，每组 = 1 张表格材料（`**（材料）**` 标题 + markdown 表格，6~8 行数据、列数 ≤4、主题为通用统计场景）配 **4~5 道题（单选或多选均可）**，编号接续综合客观题；每组内考法须不重复（增长率/增长量/比重/倍数/平均数/增速比较/合计/综合分析）；每题计算必须实际演算；材料与题目均不得含岗位专业词（规范见 `references/出题规范.md` §2.6）。

### 第 1.5 步：AI 逐题复核（知识点正确性，必须执行，不可跳过）

脚本自检只覆盖结构；**答案是否正确由本步把关**。逐题过一遍以下清单（`references/出题规范.md` §6 有完整 checklist）：

1. **单选题答案唯一**：逐一确认每个干扰项确实是错误表述，不存在"也对但有争议"的选项（这是最常见的翻车点）。
2. **计算题重算**：所有涉及数值的题（数量关系、专业计算）重新演算一遍，确保选项数值正确。
3. **规范/标准数值核对**：涉及国标/行标（如 GB 5749、GB 18918、GB 50013、GB 50268）的题，限值、单位、编号对照现行有效版本，不允许凭印象。
4. **常识与时政事实**：基于公认事实/官方已公开表述，避免有争议细节。
5. **多选题**：答案 ≥2 项；干扰项为明确错误；不会出现"全都对"的歧义。
6. **综合区纯净**：综合区文本（题干+选项）不含任何岗位专业词。
7. **解析自洽**：每题解析能推导出所选答案，不出现"解析与答案对不上"。
8. **答案落点不规律**：按题号列出答案字母序列人工扫描——任一字母占比 ≤40%、无 ABCD 周期轮转、无连续 3 个以上相同；不达标则手工调整对应题选项顺序（不改变题干与正确选项内容）。

复核发现的问题立即修正（改题、改选项或改答案），修完回到第 1.5 步重核，直到全部通过再进入第 2 步。

### 第 2 步：题库自检

```bash
python3 <skill>/scripts/check_bank.py \
  --input-dir bank --sets 3 --per-set 58 --comp 25 --prof 25 --data-groups 2 --essay 3 \
  --banned "给水,污水,水厂,滤池,污泥,曝气,管网,BOD,COD"
```

（`--banned` 传岗位专业词；`--data-groups` 为每套资料分析材料组数（默认 0 = 不加），每组配 4~5 道单选或多选（`--data-per-group` 可设基准 4 或 5）；未启用时省略 `--data-groups`，此时 `--per-set` 相应为 50；`--per-set` 须 = comp + prof + 实际资料题数（每组 4~5 × 组数）；失败则按报错修正题目后重跑，直到通过。自检通过 ≠ 知识点正确，第 1.5 步不可省略）

### 第 3 步：生成 HTML

```bash
python3 <skill>/scripts/build_exam.py \
  --name "给排水技术岗" --org "四川某环境公司" --difficulty "中等" \
  --sets 3 --per-set 58 --comp 25 --prof 25 --data-groups 2 --essay 3 \
  --store-key gps_qa_watertech \
  --input-dir bank \
  --out "给排水技术岗模拟题库-练习版.html"
```

（`--store-key` 用 `gps_qa_{岗位英文slug}` 保证每个题库独立，`--note` 可加编制说明附加文本，`--essay` 为每套问答题数，`--data-groups` 为每套资料分析材料组数（每组 4~5 题，`--data-per-group` 设基准），均与 check_bank 保持一致；未启用资料分析时省略 `--data-groups`）

### 第 4 步：自动测试

```bash
NODE_PATH=<jsdom 所在 node_modules> node <skill>/scripts/test_exam.js \
  "给排水技术岗模拟题库-练习版.html" 58 3 "给水,污水,水厂,滤池,污泥,曝气,管网,BOD,COD" 3 2 4
```

（jsdom 需可用；第 6、7 个参数分别为每套问答题数、每套资料分析材料组数（未启用时省略），第 8 个参数为每组题数基准（4 或 5）；测试覆盖：题量一致性、全题选对判对、综合区无专业词、单选/多选并存、问答题数量与参考要点、资料分析材料块（数量/表格/组首题）、复习模式进出、重置弹窗、localStorage 独立 key。全部通过才算完成）

### 第 5 步：落库 + 移动端确认 + 交付

1. **产出物统一落库**（用户约定，长期有效）：生成物写入
   `~/Documents/WorkBuddy-Outputs/模拟题库/{YYYYMMDD}-{岗位名}/`，
   文件名沿用 `{岗位}模拟题库-练习版.html`。第 3 步的 `--out` 直接指向该目录下的完整路径。
   （如 `~/Documents/WorkBuddy-Outputs/模拟题库/20260822-给排水技术岗/给排水技术岗模拟题库-练习版.html`）
2. 用 Chrome headless 或预览面板按手机视口（约 390px 宽）截图确认布局正常。
3. 用 `present_files` 打开练习版 HTML 交付，并附使用说明（按钮功能、进度保存、复习模式等）。

## 硬性规则

1. **模板资源不可重写**：`assets/qa-interact.js`（交互层）与 `assets/base-head.html`（版式）是已充分测试的模板，生成 HTML 时直接引用，不要重写；确需扩展时增量修改并跑第 4 步回归。
2. **答案单一数据源**：交互 JS 运行时从答案表 DOM 读取答案，不要在 JS 中硬编码答案。
3. **localStorage key 必须每题库唯一**（`gps_qa_` 前缀），否则不同题库进度互相污染。
4. **不生成 Word/PDF**：本 skill 只产出交互 HTML；用户如另要 Word 版，走文档 skill。
5. **质量门禁双保险**：AI 逐题复核（第 1.5 步）+ 脚本自检（check_bank）+ 自动测试（test_exam）全部通过前不交付；自检通过 ≠ 知识点正确，第 1.5 步不可省略。
6. **正确答案落点控制（源头避免规律）**：出题时就控制正确项位置（先定落点再写选项），整卷答案字母无周期、无连续 3+ 相同、任一字母 ≤40%；**禁止事后脚本轮转分配**（会形成 ABCD 周期规律）。
7. **问答题默认加上**：每套默认 3 道专业情景问答题（附参考要点），用户明确不要才去掉；问答题不判分、不进统计，仅"查看参考答案"展开。
8. **资料分析题默认不加，必须询问**：与问答题相反——表格数据分析题**默认 0 组**，生成前必须用 `AskUserQuestion` 询问用户是否增加（仅用户确定"要"才启用，默认每套 **2 组**材料）；**每组材料配 4~5 道题（单选或多选均可）**；材料块不参与判题/统计/错题清单/复习模式（仅随组首题展示）；材料与题目均属综合区，严禁岗位专业词，计算必须演算。
9. **产出物必须落库**：最终 HTML 写入 `~/Documents/WorkBuddy-Outputs/模拟题库/{日期}-{岗位名}/`，不得只留在临时工作目录。
10. 数据文件（bank/setN.md）为中间产物，保留在工作目录即可，不入交付清单。
